# Program / Account / CPI / ALT security audit — PR #17

## Scope and disposition

Reviewed branch `live-trading-policy-enforcement`. This is a static code and test review only. No wallet was connected, no transaction was signed or submitted, and no production deployment or merge was performed.

**Disposition: Stage 2 is NOT complete. Keep every live-execution path disabled.** The current code has useful fail-closed scaffolding, but it does not establish that a real Jupiter swap route is safe.

## Test review

Node tests cover legacy/v0 decoding, static-key and ALT-loaded signer/writable metadata, ALT address-index bounds and duplicate-index rejection, resolved and unresolved ALT fixtures, malformed serialized data, unknown Program/Account rejection, signer mismatch, pre-signed transaction rejection, missing semantic validators, metadata-only order results, and the standalone simulated-CPI trace validator. Trusted-resolver unit tests cover canonical owner checks, active/deactivated state, RPC endpoint pinning, slot freshness, recent extension rejection, missing accounts, malformed state, and invalid configuration.

The positive policy test uses a deliberately permissive mock validator. It proves the validator hook is called and explicit approval is required; it does **not** validate real Jupiter, Token, Associated Token, System, or DEX instruction semantics. The ALT tests use constructed fixtures and do not prove live RPC behavior.

The CPI rejection test fixture was corrected so the unknown Program ID and account remain outside their respective allow-lists. The corrected commit's CI run must complete successfully before this test suite is considered green. A successful unit-test run does not establish production RPC trust, Worker integration, or transaction safety. The legacy `solana-smart-bot` Cloudflare check has previously failed because that old Worker name does not exist; distinguish it from the current `solana-smart-bot-new` Preview result.

## Required work before Stage 2 can pass

1. Independently review the standalone trusted ALT resolver and its configuration assumptions; validate the chosen RPC provider operationally. Only then consider wiring it into trusted server configuration. Do not accept resolver, RPC response, or policy inputs from browser/Jupiter-controlled data.
2. The current code permits only Metis and requests exclusion of JupiterZ, Dflow, and OKX. Independently review the exact Metis DEX/program versions and account layouts before treating any route as supported. Review token program variants, authorities, exact input/output amounts, slippage, fees, and destination accounts.
3. Validate the full order response against the selected Metis-only policy, including `router`, `mode`, `swapMode`, transaction version, signer/fee-payer fields, gasless status, fee mint/rate, minimum output threshold, slippage, and block-height expiry. The code now requires a trusted block-height provider and checks the expiry is ahead of the current height but no more than 150 blocks away. Wire this provider to the reviewed RPC in trusted server code, then bind quote amounts, route steps, fee destinations, and token mints to decoded instruction semantics; reject missing, stale, or inconsistent metadata.
4. Implement semantic validators for those exact versions. Reject unknown instructions, optional/remaining accounts not explicitly understood, unexpected writable privileges, and unsupported token programs/extensions.
5. Wire a trusted simulation of the exact unsigned transaction into the CPI gate, bind its response to the transaction and trusted RPC context, define reviewed CPI program/account allow-lists, and reject unexpected CPI programs/accounts. The new helper is only a unit-tested validator; it is not yet integrated. Do not treat simulation alone as approval.
6. Require server-side market and risk timestamps to be fresh (30-second maximum age, 5-second future skew); wire the timestamped values to trusted scanner/RPC sources and add source-integrity tests.
7. Add adversarial token-account tests for mint mismatch, authority mismatch, wrong token-program owner, frozen state, delegates, close authorities, stale RPC context, and unsafe Token-2022 extensions; keep these checks bound to the actual source and destination accounts.
8. Wire the parsed token-account validator to trusted RPC reads and a reviewed token-program policy; validate both source and destination token accounts and mint-level Token-2022 extensions.
9. Add adversarial fixtures for fee redirection, unexpected CPI, writable privilege escalation, malformed/unknown instruction data, and stale or inconsistent quote metadata.
10. Keep the runtime isolated until reviewed immutable policy, semantic validators, CPI policy, and ALT resolver are approved. No live execution endpoint may consume caller-supplied policy functions or allow-lists.
11. Obtain independent security review before considering any signing or submission work.

## Safety invariant

Until every applicable item above is completed and independently reviewed, the live-trading module remains isolated, default-off, and non-executable. No merge, production deployment, wallet signing, or real transaction is authorized by this audit.
